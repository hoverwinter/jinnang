本仓库是一个由 Claude 维护的个人知识库，使用 `wiki-skill` 技能进行初始化与日常维护。主要语言：{{LANGUAGE}}。

## 目录结构

仓库包含两个顶层目录：

- `raw/` — 原始资料（只读）
  - `articles/` Markdown文章
  - `papers/` PDF论文
  - `transcripts/` 音频转录
  - `books/` 书籍摘录
- `wiki/` — Claude维护的知识库
  - `index.md` 内容索引
  - `log.md` 变更日志
  - `overview.md` 知识库概览
  - `concepts/` 概念页面
  - `entities/` 实体页面
  - `topics/` 主题页面
  - `sources/` 来源摘要

## 核心原则

1. **raw不可修改**：原始资料是知识源泉，只读取
2. **知识累积**：更新而非重复，标注矛盾而非覆盖
3. **双向链接**：使用 `[[页面名]]` 格式，底部维护相关页面
4. **语言一致**：概念名、分类、正文使用 {{LANGUAGE}}；专有名词/缩写保留原形
5. **日期统一**：frontmatter 与正文日期一律 `YYYY-MM-DD`

### 矛盾标注格式

不同来源观点冲突时保留双方，不要覆盖：

```markdown
> ⚠️ 矛盾：[[来源A]] 认为 X，[[来源B]] 认为 Y。
```

### 页面底部引用格式

- `## 相关来源`：`- [[来源名]] - 说明`
- `## 相关概念`：`- [[概念名]] - 说明`

## 工作流程

完整流程由 `wiki-skill` 定义，此处仅摘要。

### Ingest（摄入）

```
1. 读取raw资料 → 2. 过滤广告 → 3. 与用户讨论要点
→ 4. 创建来源摘要 → 5. 更新实体 → 6. 更新概念
→ 7. 更新索引 → 8. 记录log
```

**需要用户确认的节点**：第 3 步（要点提炼）、矛盾裁决、概念合并决策。其余步骤 Claude 可自主完成。

**必须过滤**：
- 微信号/二维码/联系方式
- "点赞/关注/转发" 等引流话术
- 课程推销、付费社群、知识星球链接
- 作者无关水印、平台广告、尾部插入的互推内容

**必须保留**：作者信息、核心内容、必要版权信息

### Query（查询）

读取 index 找页面 → 读取内容 → 回答并引用来源

### Lint（检查）

检查项：矛盾、孤立、死链、过时、统计漂移、frontmatter 缺失、分类漂移

## 内容约定

### 概念粒度

创建新概念前先判断是否为已有概念的**参数差异或子情形**。如是，作为小节更新到父概念，不要新建。仅「定义相同或仅参数差异」才合并；表达不同侧面的概念分开建页并互链。

### index.md 分类

二级分类建议采用「主题域 - 层面」命名（例如 `<主题> - 基础层面`、`<主题> - 风控层面`）。新概念归类时：

1. 优先归入已有分类
2. 同主题下若出现新维度再开新"层面"
3. 跨主题的通用概念归入思想类/方法类的综合分类

### 易踩坑点

- **log遗漏**：每次处理完成立即写 log，否则追溯困难
- **统计不同步**：index.md 的页面计数需与实际文件数一致，lint 时核对
- **链接写路径**：用 `[[概念名]]` 不用文件路径
- **大批量扫描**：先用 Agent 并行扫描，合并 JSON 后再落盘

## 页面格式要点

所有页面必须有 frontmatter：`type`、`name`、`created`、`updated`。详细模板见 `wiki-skill` 技能的 `templates/` 目录。
